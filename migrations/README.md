# migrations/

Prisma migration history for the MITHQAL v26.0 canonical schema.

## Scope

- `prisma/schema.prisma` is the source of truth for the canonical schema.
- `prisma/migrations/` holds the Prisma migration files generated by
  `prisma migrate dev`. (Prisma writes them there by default; this
  directory is for any non-Prisma SQL migrations.)
- This directory holds supplementary SQL migrations that are not
  expressible in Prisma's schema DSL (e.g. row-level security policies,
  extension installs, role grants).

## Operations

- Apply schema: `bun run db:push` (Pilot A: `prisma db push --accept-data-loss`)
- Generate client: `bun run db:generate`
- Run migrations: `bun run db:migrate`
- Reset (DESTRUCTIVE — Pilot only): `bun run db:reset`

## Rules

- NEVER run `db:reset` against a production-authorized environment.
- Migrations MUST be re-runnable; running the same migration twice
  MUST be a no-op.
- A migration that drops a column MUST be accompanied by a decision-log
  entry and a reconciliation plan for the affected rows.
