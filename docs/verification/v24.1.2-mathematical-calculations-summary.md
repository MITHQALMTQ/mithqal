# PART I — CONSTITUTIONAL SOLVENCY (Layer 1 — LEGAL)

These are the ONLY calculations that determine legal solvency. All other metrics are advisory.

---

## 1. PAR — Settlement Reference Unit

```
PAR = $1.00 (fixed, non-CPI-linked, non-gold-linked)
```

**Purpose:** PAR is the fixed USD-denominated settlement/accounting reference unit. It defines the redemption liability per MTQ token. Every MTQ is redeemable for $1.00 of reserve value (subject to reserve availability and liquidity constraints).

**Key Distinction:** USD denomination ≠ USD reserve anchor. PAR uses USD as a reference unit for settlement clarity, but the reserve portfolio is globally diversified across 11 currencies + gold + silver.

**Units:** USD per MTQ

**Constraints:** Fixed permanently. Cannot be changed by governance, optimizer, or any automated system. Only a constitutional amendment (6-of-7 Council supermajority, 90-day timelock) could theoretically change PAR — but the Constitution explicitly prohibits changing PAR.

**Specialist Review Questions:**
- Is a fixed USD PAR appropriate for a globally diversified reserve system?
- Should PAR be linked to a basket CPI instead of USD?
- What are the implications of USD PAR for purchasing-power resilience?
- Is the distinction between "USD denomination" and "USD anchor" economically sound?

## 2. Liability (L)

```
L = S × PAR
```

**Purpose:** Defines the total contractual redemption liability — the amount the institution owes to all MTQ holders if every token were redeemed at PAR.

**Inputs:**
- S = total MTQ supply (currently 54,000,000 MTQ in the model; 310.95 MTQ on Monad testnet; 1,000 MTQ on Arc testnet)
- PAR = $1.00

**Units:** USD

**Current Value:** L = 54,000,000 × $1.00 = $54,000,000

**Specialist Review Questions:**
- Is fixed-supply liability appropriate, or should liability be dynamic?
- How should liability account for pending redemptions in the pipeline?
- Should liability include accrued fees or only principal?

## 3. Market Reserve Value (R_m)

```
R_m = Σ (Q_a × P_a)
```

**Purpose:** The total mark-to-market value of all reserve assets before any haircuts or risk adjustments. This is the "what could we sell it for today" value.

**Inputs:**
- Q_a = quantity of asset a (e.g., ounces of gold, USD cash amount)
- P_a = current market price of asset a (e.g., gold spot price, FX rate)

**Units:** USD

**Constraint:** R_m ≥ R_a ≥ R_l (market ≥ adjusted ≥ stress)

**Current Value:** R_m ≈ $61,200,000 (live, from multi-oracle pricing)

**Specialist Review Questions:**
- Is mark-to-market appropriate for all asset classes, or should some use amortized cost?
- How should liquidity discounts be applied to large positions?
- Should the gold price use spot, LBMA fix, or VWAP?

## 4. Adjusted Reserve Value (R_a) — THE SOLVENCY-DETERMINING METRIC

```
R_a = Σ [Q_a × P_a × (1 - H_a) × C_a]
```

**Purpose:** The prudential reserve value after constitutional haircuts and counterparty risk adjustments. This is the value used in the Reserve Ratio (RR) calculation. R_a is THE number that determines whether MITHQAL is legally solvent.

**Inputs:**
- Q_a = quantity of asset a
- P_a = market price of asset a
- H_a = constitutional haircut (see §6 below)
- C_a = counterparty score (see §7 below)

**Units:** USD

**Constraint:** R_a ≤ R_m (always — haircuts and counterparty scores can only reduce value)

**Current Value:** R_a ≈ $59,600,000

**Specialist Review Questions:**
- Are the haircut levels appropriate for each asset class?
- Should haircuts be static or dynamic (increasing during stress)?
- Is the multiplicative counterparty formula appropriate?
- Should there be a concentration haircut on top of the per-asset haircut?

## 5. Stress Reserve Value (R_l)

```
R_l = Σ [Q_a × P_a × (1 - H_a) × C_a × S_a]
```

**Purpose:** The liquidation/stress reserve value — what the reserves would be worth under forced-sale/stress conditions. Used for Stress-NAV and stress testing.

**Inputs:**
- All inputs from R_a, plus:
- S_a = stress coefficient (see §8 below)

**Units:** USD

**Constraint:** R_l ≤ R_a ≤ R_m

**Current Value:** R_l ≈ $51,900,000 (on different allocation than R_a in current implementation — this is a known issue)

**Specialist Review Questions:**
- Are the stress coefficients calibrated to historical crisis data?
- Should R_l use a correlation-adjusted stress model instead of per-asset coefficients?
- How should R_l account for fire-sale discounts on large positions?

**Purpose:** Haircuts provide a prudential margin between market value and the value counted toward solvency. They account for price volatility, liquidity risk, and execution uncertainty.

## 7. Counterparty Risk Score (C_a)

```
C_a = Credit_a × Jurisdiction_a × Operational_a

Clamped to [0.90, 1.00]
```

**Purpose:** Adjusts reserve value for counterparty credit risk, jurisdictional risk, and operational risk. Multiplicative formulation means compounding impairments are captured.

**Inputs:**
- Credit_a = credit quality of the counterparty/issuer (0-1)
- Jurisdiction_a = jurisdictional risk score (0-1)
- Operational_a = operational risk score (0-1)

**Units:** Dimensionless (0.90 to 1.00)

**Key Property:** Multiplicative (not additive) — two simultaneous impairments compound rather than average.

**Example:**
- Credit = 0.95, Jurisdiction = 0.90, Operational = 0.95
- C_a = 0.95 × 0.90 × 0.95 = 0.81225
- Clamped to 0.90 (floor — counterparty score cannot reduce R_a by more than 10%)

**Specialist Review Questions:**
- Is the [0.90, 1.00] clamp appropriate, or should it allow deeper haircuts?
- Should the three components have different weights?
- Should there be a time-decay function (longer-duration assets get lower scores)?
- How should C_a interact with the EffectiveCustodyRisk model (Layer 1)?

## 8. Stress Coefficients (S_a)

```
S_a is a per-asset-class stress multiplier applied for R_l:

| Asset Class              | Stress Coefficient (S_a) |
|--------------------------|--------------------------|
| Cash                     | 0.95                     |

| Gold                     | 0.85                     |

| Stablecoin               | 0.80                     |

```

**Purpose:** Models the expected value realization under forced-sale/stress conditions. A coefficient of 0.85 means the asset is expected to realize 85% of its adjusted value under stress.

**Specialist Review Questions:**

## 9. Reserve Ratio (RR) — THE SINGLE LEGAL SOLVENCY METRIC

```
RR = R_a / (S × PAR) = R_a / L
```

**Purpose:** RR is the ONLY legal solvency metric. It determines whether MITHQAL can legally continue minting, whether emergency governance activates, and whether redemption throttling engages.

**Thresholds:**
- RR ≥ 100% = Constitutional floor (hard invariant — auto-pauses minting if breached)
- RR ≥ 105% = Policy target
- RR ≥ 120% = Strategic target (20% excess reserve value over contractual liabilities)

**Units:** Percentage

**Current Value:** RR ≈ 110.25% (live from production)

**Critical Property:** RR is NOT tautological. It uses PAR-based liability (not NAV-based). RR is NOT replaced by GEI, CBGRS, BRI, GACR, or any advisory metric.

**Specialist Review Questions:**
- Is 120% strategic target sufficient given stress-test failures at custody/correlation scenarios?
- Should the 100% floor have a grace period or immediate auto-pause?
- How should RR account for pending but unsettled mint/redeem operations?
- Is the 20% strategic buffer appropriate for a multi-currency + bullion + stablecoin portfolio?

## 10. Stress-RR (Hard Planning Constraint)

```
RR_stress(s) = R_a(s) / (S(s) × PAR)
```

**Purpose:** Forward-looking scenario solvency. For every defined stress scenario s, Stress-RR must be ≥ 100%. This is a PLANNING constraint, not a second legal solvency ratio.

**Key Distinction:** Stress-RR uses R_a (adjusted, with haircuts and counterparty scores) — NOT R_l (stress reserve). A portfolio can pass Stress-RR ≥ 100% while R_l < 100%.

**Specialist Review Questions:**
- Should Stress-RR use R_l instead of R_a for more conservatism?
- What is the appropriate per-scenario floor (100% or higher)?
- How should Stress-RR account for correlation breaks?

---

## 11. Required RR (Diagnostic)

```
RR_required_scenario = 1 / (1 - scenario_loss)
```

**Purpose:** Diagnostic metric that calculates what RR would be needed to survive a given loss without breaching the 100% floor.

**Examples:**
- 20% loss → RR_required = 1 / 0.80 = 125%
- 30% loss → RR_required = 1 / 0.70 = 142.86%
- 50% loss → RR_required = 1 / 0.50 = 200%

**Specialist Review Questions:**
- Is this formula correct for fixed-liability scenarios?
- How should it account for liability changes (redemption reduces both assets and liabilities)?
- Should it use R_a loss or R_m loss?

## 13. Gold-Equivalent Index (GEI)

```
GEI_t = (R_a,t / G_t) / (R_a,0 / G_0)
```

**Purpose:** Measures whether the adjusted reserve is growing faster or slower than gold. GEI > 1.0 means reserves are outpacing gold (purchasing power increasing relative to gold). GEI < 1.0 means reserves are losing ground vs gold.

**Inputs:**
- R_a,t = adjusted reserve value at time t
- G_t = gold spot price at time t (multi-oracle consensus)
- R_a,0, G_0 = base-date values (base date: 2026-08-12)

**Units:** Dimensionless (normalized to 1.0 at base date)

**Current Value:** GEI ≈ 0.936 (reserves losing ground vs gold — expected since gold rallied)

**Classification:** Advisory only. Does NOT trigger rebalancing. Does NOT change PAR.

**Specialist Review Questions:**
- Is R_a/Gold the right ratio, or should it be R_m/Gold?
- Should the base date be rolling (365-day) or fixed?
- How should GEI account for currency diversification (gold in different currencies)?

## 14. Bullion Resilience Index (BRI)

```
BRI = (GoldVal_t / GoldVal_0)^w_g × (SilverVal_t / SilverVal_0)^w_s

Where:
  w_g = 0.90 (CVaR-optimized, 10k correlated paths)
  w_s = 0.10 (CVaR-optimized)
  w_g + w_s = 1.0
```

**Purpose:** Measures the resilience of the bullion reserve (gold + silver) relative to a base date. The 90/10 weights were optimized via 10,000 correlated Monte Carlo paths to minimize CVaR.

**Inputs:**
- GoldVal_t = gold holdings × gold price at time t
- SilverVal_t = silver holdings × silver price at time t
- GoldVal_0, SilverVal_0 = base-date values

**Units:** Dimensionless (normalized to 1.0 at base date)

**Classification:** Advisory only. Does NOT trigger rebalancing. Does NOT drive the optimizer.

**Specialist Review Questions:**
- Are the 90/10 weights appropriate, or should they be dynamic (CVaR-based)?
- Should BRI include a volatility adjustment?
- How should BRI account for physical custody risk?

## 15. Currency Basket Gold-Relative Strength (CBGRS)

```
CBGRS_t = PRODUCT[ G_i(t) ^ w_i(t) ]    for all active eligible reserve currencies i

Where:
  G_i(t) = [(Currency_i / Gold)_t] / [(Currency_i / Gold)_0]
  w_i(t) = FINAL reserve-currency weight (after all pipeline stages)
  Σ w_i(t) = 1.0000 (required invariant)
```

**Purpose:** Measures the aggregate strength of the eligible reserve-currency basket relative to gold. CBGRS > 1.0 means the basket is strengthening vs gold. CBGRS < 1.0 means the basket is weakening.

**Canonical Method:** Weighted geometric mean (preserves multiplicative/compounding behavior)

**Diagnostic (NOT canonical):**
```
CBGRS_arithmetic = Σ [ w_i(t) × G_i(t) ]    (diagnostic only)
```

**Units:** Dimensionless (normalized to 1.0 at base date)

**Current Value:** CBGRS ≈ 0.973 (basket weakening vs gold by ~2.7%)

**Per-currency gold-relative depreciation:**
```
D_i(t) = 1 - G_i(t)
```

**Classification:** Advisory only (Layer 2). Does NOT replace RR. Does NOT trigger rebalancing independently. Does NOT modify PAR.

**Specialist Review Questions:**
- Is the geometric mean superior to arithmetic mean for this application?
- Should the weights include gold/silver, or only fiat currencies?
- How should CBGRS handle currency exits (renormalization)?
- Should CBGRS have a threshold for "structural weakness" warning?

## 16. Gold-Adjusted Coverage Ratio (GACR)

```
GACR = (R_a / G_t) / (S × PAR / G_t) = R_a / (S × PAR) = RR
```

**Purpose:** Expresses RR in gold terms. The algebra intentionally collapses to RR — GACR is a REPORTING metric, not a new solvency measure.

**Classification:** Reporting only. Algebraically identical to RR.

**Specialist Review Questions:**

## 17. Liquidity Coverage Ratio (LCR)

```
LCR = HQLA / 30-day net outflows

Where:
  HQLA = cash + sovereign × approved_liquidity_factor + eligible_digital × approved_liquidity_factor
  30-day net outflows = expected_redemptions - expected_inflows + operational_adjustments
```

**Purpose:** Measures whether the institution can survive 30 days of stressed redemptions using high-quality liquid assets. Gold and silver are excluded from base HQLA unless independently validated as immediately realizable.

**Thresholds:**
- LCR ≥ 1.00 = Hard floor (constitutional)
- LCR ≥ 1.25 = Policy target
- LCR ≥ 2.00 = Strategic target (policy, NOT constitutional)

**Units:** Dimensionless (ratio)

**Current Value:** LCR ≈ 7.0 (very strong — but computed from hardcoded outflows; needs scenario calibration)

**Specialist Review Questions:**
- Is the 10% expected redemption assumption appropriate, or should it be scenario-calibrated?
- Should HQLA include gold with a deep haircut (e.g., 50%)?
- What is the appropriate liquidity factor for stablecoins?
- Should LCR have a currency-mismatch adjustment?

---

## 18. Liquidity Reserve Ratio (LRR)

```
LRR = Immediately Available Liquidity (IAL) / Expected 30-Day Redemption Demand
```

**Purpose:** Complements LCR by explicitly excluding gold and silver (Bullion Protection Rule). Measures whether non-bullion liquid assets can cover redemption demand.

**Thresholds:**
- LRR ≥ 1.2 = Strong
- LRR ≥ 1.0 = Compliant
- LRR ≥ 0.9 = Marginal
- LRR < 0.9 = Critical

**Specialist Review Questions:**
- Is the Bullion Protection Rule (always exclude gold/silver from immediate liquidity) appropriate?
- Should IAL include prefunded redemption liquidity?
- How should LRR account for banking settlement latency?

LCI = HQLA / Expected Stress Outflows

## 23. Stablecoin Adjusted Exposure (SAE)

```
SAE = Σ (Stablecoin Value × DRQS_i⁻¹ × StressFactor) / R_a × 100%

Where:
  StressFactor = 1 + (10 - DRQS) / 10
```

**Purpose:** Risk-adjusted stablecoin exposure. A stressed stablecoin (low DRQS) has higher effective risk weight than its nominal allocation. Prevents underestimating stablecoin risk.

**Example:**
- USDC (DRQS=8.5): StressFactor = 1 + 1.5/10 = 1.15 → effective weight = 1/8.5 × 1.15 = 0.135
- DAI (DRQS=6.25): StressFactor = 1 + 3.75/10 = 1.375 → effective weight = 1/6.25 × 1.375 = 0.220

**Specialist Review Questions:**
- Is DRQS⁻¹ the right risk-weighting formula? It gives units of 1/score, which is not directly comparable to SE.
- Should StressFactor use a different functional form (e.g., exponential)?
- How should SAE interact with the stablecoin state machine?

## 26. Residual-Risk Optimization Objective

```
W* = argmin [ λ₁·CVaR + λ₂·FXRisk + λ₃·GeoRisk + λ₄·ConcentrationRisk + λ₅·LiquidityCost + λ₆·ExecutionCost ]
```

**Purpose:** After all hard constraints are satisfied, minimize residual portfolio risk. The optimizer NEVER sacrifices solvency, liquidity, concentration limits, eligibility, sanctions compliance, or custody requirements for better theoretical return.

**Key Principle:** Constitutional feasibility first. Risk optimization second. Execution last.

**Specialist Review Questions:**

- How should the optimizer handle regime changes (switching covariance matrices)?

## 28. Marginal Reserve Risk Contribution (MRRC)

```
MRRC_i = CVaR(W) - CVaR(W with marginal reduction in asset i)

Implementation: finite-difference with ε = 0.01 (1% marginal reduction)

Portfolio CVaR (normal approximation):
  CVaR_α ≈ -μ + (φ(z_α) / α) × σ

Where:
  μ = portfolio expected return
  σ = portfolio standard deviation
  z_α = z-score for confidence level (1.645 for 95%, 2.326 for 99%)
  φ(z_α) = standard normal PDF at z_α
  α = significance level (0.05 for 95%, 0.01 for 99%)
```

**Purpose:** Identifies which assets contribute most to portfolio tail risk. The rebalancer reduces assets with excessive marginal risk contribution — this is more important than reducing assets merely because they depreciated.

**Risk Contribution %:**
```
RiskContributionPct_i = MRRC_i / Σ MRRC_j    (normalized to 100%)
```

**Specialist Review Questions:**
- Is the normal approximation appropriate, or should CVaR use historical simulation / Monte Carlo?
- Should ε be 1% or smaller (0.1%)?
- How should MRRC handle correlation changes during stress?
- Should MRRC use Cornish-Fisher expansion instead of normal approximation?

## 29. Principal Eigenvalue Monitoring

```
EI_t = λ₁(Σ_t) / λ₁(Σ_baseline)

Where:
  λ₁ = principal (largest) eigenvalue of the covariance matrix Σ
  EI = Eigenvalue Index

States:
  Normal:    EI < 1.25
  Elevated:  1.25 ≤ EI < 1.50
  High:      1.50 ≤ EI < 1.75
  Crisis:    EI ≥ 1.75
```

**Purpose:** As λ₁ increases, the portfolio is increasingly dominated by a common risk factor (correlation is rising). When EI enters Crisis, the reserve engine activates crisis protocols: MRRC switches to crisis model, digital risk reviewed, custody limits tighten, gold corridor can rise, issuance capacity falls.

**Concentration Ratio:**
```
ConcentrationRatio = λ₁ / Σ λ_i
```
(Higher = more concentrated risk)

**Specialist Review Questions:**
- Is power iteration sufficient for computing eigenvalues, or should we use QR decomposition?
- How should the baseline covariance matrix be calibrated?
- Should EI use a rolling window (e.g., 90-day) or fixed baseline?
- What are appropriate thresholds for EI states?

## 30. Cornish-Fisher Tail-Risk Diagnostic

```
VaR_CF = μ + σ × [z + (z²-1)/6 × S + (z³-3z)/24 × (K-3) - (2z³-5z)/36 × S²]

Where:
  S = skewness
  K = kurtosis (excess kurtosis = K - 3)
  z = z-score (1.645 for 95%, 2.326 for 99%)

TailExpansion = |VaR_CF / (μ + σ × z)|    (ratio of CF VaR to normal VaR)
```

**Purpose:** Adjusts Value-at-Risk for non-normality (skewness and kurtosis). When tail expansion > 1, the normal approximation underestimates tail risk.

**Specialist Review Questions:**
- Is Cornish-Fisher appropriate for multi-asset portfolios with complex dependencies?
- Should we use a copula-based approach instead?
- How should skewness and kurtosis be estimated (sample vs. GARCH)?

# PART VIII — CALM (Capital-Adaptive Liability Management)

## 31. CALM — Dynamic Supply Cap

```
S_max,t = R_a,t / (RR_target,t × PAR)

Headroom_t = S_max,t - S_t

Where RR_target is state-dependent:
  NORMAL:      RR_target = 1.15

**Purpose:** Prevents the liability side from expanding beyond current reserve risk capacity. CALM is a SECONDARY defense — it does NOT replace RR and does NOT permit undercollateralization.

**Critical Direction:** Risk↑ → RR_target↑ → MintCapacity↓ (NEVER Risk↑ → MintCapacity↑)

# PART IX — CUSTODY RISK (Layer 1)

---

## 32. Effective Custody Risk

```
EffectiveCustodyRisk = Exposure × LGD × CommonMode × (1 - RecoveryFactor)

Where:
  Exposure = fraction of total reserve at this custodian (0-1)
  LGD = Loss Given Default (0-1, NEVER 0 — residual risk always exists)
  CommonMode = common-mode dependency factor (0-1)
  RecoveryFactor = expected recovery from insurance/legal (0-1)
```

**Purpose:** Replaces the raw 15% custody cap with a richer model that accounts for loss severity, common-mode dependencies, and recovery expectations.

**Hard Cap:** 15% per custodian (preserved)

**Sovereign/Direct Custody:** 0 ≤ CBExposure ≤ 50% (conditional on actual legal availability)

**Key Principle:** "Zero commercial default risk" is rejected as too absolute. Residual legal, operational, and access risks are always separately modeled.

**Specialist Review Questions:**

- How should CommonMode be calculated (same cloud? same bank? same jurisdiction?)
- Should RecoveryFactor be dynamic based on insurance market conditions?
- Is 15% hard cap appropriate, or should it be risk-adjusted (lower for riskier custodians)?

# PART X — EXTERNAL RISK TRANSFER (Layer 6)

---

## 33. ERTF Net Recovery

```
NetRecovery = PolicyLimit × TriggerProbability × RecoveryFactor

Risk-Adjusted Recovery = NetRecovery × (1 - CounterpartyRiskScore × 0.5) × (1 - BasisRisk × 0.3)
```

**Purpose:** Models the expected recovery from external risk transfer instruments (insurance, Takaful, parametric coverage, guarantees). NOT a guaranteed T+0 payment.

**Key Risks Modeled:**
- Basis risk: trigger fires but loss doesn't occur (or vice versa)
- Counterparty risk: the reinsurer itself can fail
- Oracle risk: who determines the custodian default occurred?
- Liquidity risk: does the contract actually hold liquid collateral?
- Jurisdiction risk: can funds legally be transferred immediately?

**ERTF Properties:**
- Legally separate from monetary reserve
- Does NOT count toward R_a
- Does NOT affect PAR
- NOT required for ordinary MTQ redemption

**Specialist Review Questions:**

- What trigger probabilities are realistic for parametric custody insurance?

# PART XI — IN-KIND DELIVERY (Layer 7)

## 34. In-Kind Emergency Reserve Delivery

```
InKindValue = MarketValue(DeliveredAssets)    NOT InKindValue = PAR

ProRataShare = MTQAmount / TotalSupply
MarketValueUsd = TotalReserveValueUsd × ProRataShare

DiscountToPar = (ParValue - MarketValue) / ParValue    (if reserves < PAR)
PremiumToPar = (MarketValue - ParValue) / ParValue     (if reserves > PAR)
```

**Purpose:** Emergency mechanism for formally defined resolution/extraordinary liquidity events. Delivers pro-rata reserve assets instead of cash when banking rails are frozen.

**Critical Constraint:** In-kind delivery does NOT guarantee 100% PAR. If reserves have declined to $0.82 per MTQ, in-kind delivery gives $0.82 of assets, not $1.00.

**Activation Conditions:**
- Formally declared resolution or extraordinary liquidity event
- Cash/stablecoin redemption unavailable or insufficient
- 4-of-5 institutional governance approval
- Transparent mark-to-market valuation at delivery time

**MiCA Compatibility:** MiCA allows redemption through delivery of referenced assets in specified circumstances, but requires stressed-redemption procedures.

**Specialist Review Questions:**

# PART XII — REBALANCING CONTROLS

## 35. Hysteresis (Anti-Whipsaw)

```
If |proposed_weight - current_weight| ≤ 2%:
    NO ACTION (within hysteresis band)

If |proposed_weight - current_weight| > 2%:
    Increment confirmation counter
    If counter ≥ 2 consecutive cycles in same direction:
        Execute rebalance
    If direction reverses:
        Reset counter to 0
```

**Purpose:** Prevents rapid oscillation (whipsaw) in reserve allocation. A weight change must persist for 2 consecutive evaluation cycles in the same direction before executing.

**Specialist Review Questions:**
- Is the 2% band appropriate for all asset classes?
- Should the band be wider for volatile assets (silver) and narrower for stable assets (cash)?
- What is the appropriate evaluation cycle frequency (daily? weekly?)

## 36. Trade Suppression

    SUPPRESS (unless emergency override)

Emergency overrides: SDP, Constitutional Emergency, concentration_cap, RR<100%, minimum_floor
```

**Purpose:** Prevents rebalancing when the cost of trading exceeds the risk-reduction benefit.

## 37. Severe Deviation Protocol (SDP)

```
If |P_t / P_{t-7} - 1| > 5%:
    SDP triggers
    K_SDP = P_reference / P_current
    W_emergency = C_structural × K_SDP
    W_new = max(W_emergency, W_current × 0.50)
    Currency lifecycle: full → suspended
```

**Purpose:** Emergency protocol for severe currency price deviations (>5% in 7 days). Reduces exposure to the deviating currency while preserving a minimum 50% of current weight.

**Specialist Review Questions:**
